## Cómo se elige el modo
`resolveMode(location.search)`:

| URL | Modo |
|---|---|
| sin `token`, o `?token=` vacío | `mock` |
| `?mock=1` (o `?mock`, `?mock=true`), con o sin token | `mock` |
| `?token=…` sin mock (o `?mock=0`) | `live` |

En `mock` no se ejecuta ni una línea del SDK y no sale ninguna petición: el SDK solo se carga en `live`, con
`import()` dinámico dentro de `init()`.

## API del puente
```ts
createBridge({ search?, storage?, now?, sdkLoader?, random?, env?, origin?, apiBaseUrl?, publicGameKey? }): FunticoBridge
resolveMode(search: string): 'mock' | 'live'

bridge.mode                                              // 'mock' | 'live'
bridge.init(): Promise<FunticoResult<FunticoMode>>      // idempotente
bridge.getUser(useCache?)                                // { UserId, PlatformId, Name, AvatarUrl }
bridge.completePractice(score, { collected?, gameEvents?, sessionId? })
bridge.getHallOfFame({ period?: 'global'|'monthly', page?, limit?, gameMode?: 'all'|'practice'|'rooms'|'special' })
bridge.createSession(json, 'Practice'|'Rooms'|'Tournament', eventId, saveSessionId)
bridge.updateSession(json)
bridge.getUnfinishedSessions()
bridge.reconnectSession(id)                              // estado descifrado
bridge.getSession()                                      // atajo: { session, json } | null
bridge.closeSession(); bridge.recordEvent(info); bridge.getRecordedEvents()
bridge.getCampaignAvailability(useCache?); bridge.getCampaignLevels(useCache?)
bridge.startCampaignLevel(levelId); bridge.getActiveCampaignAttempt()
bridge.completeCampaignLevel(metrics, attempt?)
```
Todo lo asíncrono resuelve a `{ ok: true, value }` o `{ ok: false, error: { code, message, campaignCode? } }`
con `code` ∈ `network | rejected | campaign | invalid | not_initialized | sdk_load`. Nunca lanza hacia la escena.
Los datos son los tipos del SDK tal cual (`HallOfFameResponse`, `SavedSessionResponse`,
`CampaignLevelsViewModel`, `CampaignCompletionResult`…), importados con `import type`.

**Simulado:** usuario `Test Pilot #NNNN` persistido; Practice + Hall of Fame (8 rivales fijos + la mejor
marca del jugador, puntos desc y en empate gana quien llegó antes; mensual por mes UTC); sesiones con la
ventana de 15 min del SDK; campaña de 5 capítulos (el 1 abierto; estrellas con las reglas propuestas en el
concepto; `MinDurationSeconds` 0). Claves de `localStorage`: `adrian_adventure_funtico_{user, practice_runs,
sessions, campaign, campaign_attempt}`. Si el storage lanza, sigue en memoria.

**Live:** `apiBaseUrl` = `<origin>/save-api/funtico`, entorno `staging` por defecto (`env: 'prod'`),
`privateGameKey` = `FUNTICO_PLACEHOLDER` (relleno público), `publicGameKey` = `FUNTICO_PUBLIC_PLACEHOLDER`
hasta tener la de staging. El token sale de `?token=`, no se guarda y se tacha de los mensajes de error.
No probado contra Funtico (sin claves): solo con un SDK falso en los tests.

## Mapeo puente → SDK
| Puente | SDK (`FunticoSDK.Instance`) |
|---|---|
| `init()` | `Initialize(config)` (dentro: `Authentication(token)` + `GetUserData`/`GetBalance`/`GetVouchers`) |
| `getUser(useCache)` | `GetUserData(useCache)` (`AvatarUrl` siempre null: el SDK no lo expone) |
| `completePractice(score, opts)` | `CompletePractice(score, { collected, gameEvents })` |
| `getHallOfFame(q)` | `GetHallOfFame(HallOfFamePeriodMode, page, limit, HallOfFameGameModeFilter)` |
| `createSession(json, type, eventId, saveId)` | `CreateSession_Client(json, GameTypeEnum[type], eventId, saveId)` |
| `updateSession(json)` | `UpdateSession_Client(json)` |
| `getUnfinishedSessions()` | `UserHasUnfinishedSession_Client()` |
| `reconnectSession(id)` | `ReconnectToUnfinishedSession_Client(id)` |
| `getSession()` | los dos anteriores (atajo propio) |
| `closeSession()` | `CloseCurrentSession_Client()` |
| `recordEvent(info)` / `getRecordedEvents()` | `RecordEvent_Client(info)` / `GetCurrentSessionEvents_Client()` |
| `getCampaignAvailability(c)` / `getCampaignLevels(c)` | `GetCampaignAvailability(c)` / `GetCampaignLevels(c)` |
| `startCampaignLevel(id)` / `getActiveCampaignAttempt()` | `StartCampaignLevel(id)` / `GetActiveCampaignAttempt()` |
| `completeCampaignLevel(m, a)` | `CompleteCampaignLevel(m, a)` |

Lo que NO existe en el SDK y no se inventa en live: `PracticeOptions.sessionId` (el SDK crea su propio `RunId`;
en live se ignora), avatar del jugador, `getSession()` como llamada única.
