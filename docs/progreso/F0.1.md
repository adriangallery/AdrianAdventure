# F0.1 · Build `funtico` aislado (plan FUNTICO_ADVENTURE)

Build aparte para Funtico, servido en otro subdominio, sin tocar el juego actual.

## Qué se hizo
- **Entrada propia**: `funtico/index.html` (viewport móvil, sin scroll, `noindex`, nada web3, cache-buster propio que
  conserva `?token=` al recargar) y `src/funtico/main.ts` (escena provisional «ZEROadventure · Funtico» con
  `Scale.RESIZE`, que se recoloca al girar o redimensionar). El menú real y Triage llegan en F1.2.
  `index.html` y `src/main.ts` no cambian.
- **`vite build --mode funtico`** (`vite.config.ts` pasa a `defineConfig(({ mode }) => …)`): outDir `dist-funtico`,
  única entrada `funtico`. El plugin `funticoRootHtmlPlugin` (solo en ese modo) sube `funtico/index.html` a la raíz
  del outDir y cambia sus rutas `../assets/…` por `./assets/…`; en `vite --mode funtico` sirve esa entrada en `/`.
  `buildHashPlugin` escribe `version.txt` en el outDir resuelto (antes, fijo en `dist/`).
  Con cualquier otro modo: mismas entradas (main + stats), mismo outDir y mismos plugins que antes.
- **`IS_FUNTICO`** (`src/config/platform.ts`): sale de la constante de compilación `__IS_FUNTICO__` (`define` de
  vite, `true` solo con `--mode funtico`; guarda `typeof` para los tests de Node). Con ella `IS_WEB`,
  `WEB3_ENABLED` y `WEB3_WRITES_ENABLED` son `false`, como en Steam. En el build normal se pliega a `false`.
  Única diferencia del build normal: el `define` nuevo (`__IS_FUNTICO__: false`), necesario para que se pliegue.
- **Scripts**: `build:funtico` (`tsc && vite build --mode funtico && cp -r assets dist-funtico/`) y
  `check:no-funtico` (`scripts/check-no-funtico.mjs [dir]`: falla si un `.js/.html/.css/.json/.txt/.webmanifest`
  servido lleva «funtico» sin distinguir mayúsculas; los `.map` no cuentan). Su test,
  `tests/check-no-funtico.test.mjs`, va en `test:lint`.
- **Docker**: `Dockerfile.funtico` + `nginx.funtico.conf` (sin `/stats`, `X-Robots-Tag: noindex`); el `Dockerfile`
  normal no cambia. `dist-funtico` en `.dockerignore` y `.gitignore`.
- **CI** (`build.yml`, job `build`): `npm run check:no-funtico` tras el build normal y un paso que compila el build
  funtico y comprueba que `dist-funtico/index.html` existe en la raíz y referencia `assets/funtico-*.js`.

## Cómo se comprueba
```sh
npx vite build && node scripts/check-no-funtico.mjs dist     # limpio
npx vite build --mode funtico && ls dist-funtico/index.html   # en la raíz, con ./assets/funtico-*.js
npm run test:lint                                             # incluye el test del check
docker build -f Dockerfile.funtico .                          # imagen del subdominio (F0.3)
```
